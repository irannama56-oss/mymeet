# 2026-10-05 — mymeet (Aura Meet) join-flow bug hunt

## Reported symptoms
- "Join doesn't work — a new room gets created."
- "Two people can't be in the same meeting at the same time."

## Root causes found (all real, verified by reading code + git history)
1. **No realtime backend configured.** Only `.env.example` existed; `getSupabaseClient()`
   returned null, so `SignalingService` fell back to `BroadcastChannel` — same-browser tabs
   only. Two devices could never see each other, which looks exactly like "everyone gets
   their own room".
2. **Room discovery was deleted in commit `d5d454b`.** The `room-probe` / `room-state`
   handlers were removed, so a guest typing any code was dropped straight into an empty
   room with no existence check → "a new room gets created".
3. **The knock/lock flow was dead code.** `waitingStatus` was never set to `'waiting'`,
   `join-request` was never sent, and `requireHostApproval` was never enforced.
4. **No TURN server.** STUN-only ICE cannot traverse symmetric NAT / mobile carriers.
5. **`getUserMedia` was awaited before `setInMeeting(true)`**, so a slow/dismissed camera
   permission prompt made the Join button look broken.
6. **Stale `handleSignalingMessage` closure**: `signaling.connect()` pushed the handler once,
   so `screenSharingParticipantId` / `isChatOpen` were frozen at join time.
7. **`Lobby` effect force-reset `isCreatingNew`**, making the "New Meeting" tab unreachable
   when the page was opened from a room link.
8. **Any URL path segment was treated as a room code** (`/app`, `/preview` → rooms).
9. `toggleVideo` matched senders by `s.track?.kind === 'video' || s.track === null`, which
   could grab the audio transceiver.

## Changes made
- `src/lib/types.ts`: added `isRoomCodeLike()` guard.
- `src/lib/supabase.ts`: rewritten `SignalingService` — connection status + retry/backoff,
  Supabase **Presence** as a second discovery channel, `resetSupabaseClient()`, hardened
  `isSupabaseReady()` (rejects template values), no duplicate handler registration.
- `src/lib/webrtc.ts`: TURN support (`VITE_TURN_URL/USERNAME/CREDENTIAL`, OpenRelay default),
  always-reserved sendrecv audio+video transceivers so late media still flows via
  `syncLocalTracksToPeers()`, `getUserMedia` retry on `NotReadableError`, ICE restart on
  failure, transceiver-based sender lookup.
- `src/App.tsx`: join flow rework — guest probes the room, enters if unlocked, knocks if
  locked, or gets an explicit "Meeting not found" modal; meeting opens immediately and media
  is fetched afterwards; handler-ref pattern kills stale closures; probe timers cleaned up.
- `src/components/RoomNotFoundModal.tsx`, `src/components/ConnectionBanner.tsx`: new.
- `src/components/Lobby.tsx`: tab logic fixed; shows the transport warning.
- `.env` (gitignored) + `.env.example`: documented Supabase + TURN variables.

## Still required from the user
Fill `.env` with `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY` (and add the same vars in
Vercel → Settings → Environment Variables), otherwise remote join cannot work.

## Verification
`npm run build` (tsc + vite) passes. Room-code helpers unit-checked via node
`--experimental-strip-types`. `vite preview` serves `/` and `/<slug>` (SPA fallback) with 200.
No headless browser was available, so the two-participant flow was not executed end-to-end.

# 2026-10-05 (later) — full-codebase bug sweep

Second pass after "it still has more bugs". Audited every file in `src/` and fixed 20+ issues.
Highest-impact ones:

1. **Renegotiation loop** — presence heartbeats re-announce every peer every 3 s, and
   `createPeerConnection` re-offered whenever `signalingState === 'stable'`. Every already
   connected peer got a new offer every 3 s. Guarded with `currentRemoteDescription` +
   a per-peer `negotiating` Set (createOffer is async, so two messages in one tick both saw
   "stable"). `force` flag kept for the ICE-restart re-offer.
2. **Echo / hearing yourself** — `VideoGrid` passed `isLocal={isSharerLocal && !isScreenSharingActive}`,
   which is always false in the spotlight branch, so a self-pinned or locally screen-shared tile
   rendered an unmuted `<audio>` bound to your own mic/screen audio. Now keyed on identity.
3. **Black tile after video returns** — `<video>` unmounts while the avatar placeholder shows, so
   the `[stream]`-keyed effect never re-fired. Switched to a callback ref.
4. **Camera could never be re-enabled** after joining with it off (no track to `enable()`), and
   `getUserMedia({audio:false, video:false})` throws. Added `ensureVideoTrack`/`ensureAudioTrack`
   and an empty-stream start.
5. **Stopped screen track kept being sent** — `syncLocalTracksToPeers` only replaced when a track
   existed; now pushes `null` deliberately.
6. **Ghost participants** — added `pagehide`/`beforeunload` `peer-left` plus a 45 s last-seen
   prune (skipped while our own transport is unhealthy; generous because background tabs are
   timer-throttled).
7. **ICE `failed` fell through to `closePeer`**, making the restart pointless; `disconnected` now
   gets a 5 s grace period.
8. **Leaks** — synthetic-stream `requestAnimationFrame` loop never cancelled; analyser source
   never disconnected; media acquired after leaving was never stopped; emoji timers.
9. **Stale render state in toggles** (audio/video/hand/lock) — all now read `localParticipantRef`.
10. **Double `getDisplayMedia`** from a double click; **double join chime**; **`alert()` on kick**
    (now `NoticeModal`); **Supabase singleton never reset** after saving creds in Settings;
    **invalid `rounded-*-xs`** classes; **`animate-in` classes with no plugin installed** (added the
    CSS); **`body{overflow:hidden}`** clipped the Lobby on short screens.
11. Added `chat-history` so late joiners see the existing conversation, and a two-step confirm
    before a host kick.

New files: `src/components/NoticeModal.tsx`.
Build passes; served bundle verified via `vite preview`.

Reusable diagnostic checklist written to `~/.workbuddy-ai/skills/webrtc-mesh-join-diagnosis/`.
